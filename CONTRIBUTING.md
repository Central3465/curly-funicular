## Code of Conduct

Please be respectful and constructive in your interactions with other contributors. We are committed to providing a welcoming and inclusive environment for everyone.

## How to Contribute

There are many ways to contribute to this project:

- **Report bugs**: If you find a bug, please open an issue with a clear description and steps to reproduce it.
- **Suggest features**: Have an idea for improvement? Open an issue to discuss it.
- **Fix bugs**: Look for issues labeled "bug" or "help wanted" and submit a fix.
- **Improve documentation**: Help make the documentation clearer and more comprehensive.
- **Add tests**: Improve test coverage to ensure code quality.

## Development Setup

1. Fork the repository
2. Clone your fork:
   ```bash
   git clone https://github.com/your-username/curly-funicular.git
   cd curly-funicular
   ```
3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
4. Create a new branch:
   ```bash
   git checkout -b feature/your-feature-name
   ```
5. Make your changes and test thoroughly
6. Commit your changes:
   ```bash
   git commit -m "Add some feature"
   ```
7. Push to your fork:
   ```bash
   git push origin feature/your-feature-name
   ```

## Coding Standards

- Follow PEP 8 style guidelines for Python code
- Write clear, descriptive commit messages
- Comment complex logic but prefer self-documenting code
- Ensure all existing tests pass before submitting
- Add tests for new functionality when applicable

## Submitting Changes

1. **Create a Pull Request (PR)**: Submit your PR against the main branch
2. **Describe your changes**: Include a clear description of what your PR does
3. **Reference issues**: Link to any related issues using keywords like "Fixes #123"
4. **Wait for review**: Maintainers will review your code and may request changes
5. **Address feedback**: Make requested changes and push updates to your branch
6. **Approval and merge**: Once approved, your PR will be merged

### Pull Request Checklist

Before submitting your PR, please ensure:

- [ ] Your code follows the project's coding standards
- [ ] All existing tests pass
- [ ] You've added tests for new functionality (if applicable)
- [ ] Your commit messages are clear and descriptive
- [ ] You've updated documentation if needed
- [ ] You've disclosed any AI assistance used (see below)

## AI Use Disclosure

**We require transparency about AI-assisted contributions.**

If you use AI tools (such as large language models, code generation tools, or automated assistants) to help write code, documentation, or other contributions, you **must disclose this** when submitting your contribution. AI-assisted work should not be presented as purely human-written.

### When Submitting a PR with AI-Assisted Content:

1. **Clearly indicate** which parts of your contribution were AI-assisted in your PR description
2. **Verify and test** all AI-generated code before submission
3. **Take responsibility** for understanding and maintaining any AI-assisted contributions
4. **Do not** present AI-generated work as entirely your own

Example disclosure in a PR description:
```markdown
## AI Assistance Disclosure
- The initial implementation of the decoder function was assisted by GitHub Copilot
- Documentation drafts were generated using ChatGPT and then manually reviewed and edited
- All code has been tested and verified by the contributor
```

This policy ensures:
- Transparency and trust within the community
- Accountability for all code in the codebase
- Proper review and verification of AI-generated content

## Reporting Bugs

When reporting bugs, please include:

- A clear, descriptive title
- Steps to reproduce the issue
- Expected behavior vs. actual behavior
- Environment details (OS, Python version, browser if applicable)
- Screenshots or error messages if relevant

## Suggesting Features

When suggesting new features, please include:

- A clear description of the feature
- Why this feature would be useful
- Any examples or mockups if applicable
- Potential implementation considerations
